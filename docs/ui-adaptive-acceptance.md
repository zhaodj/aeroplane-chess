# 自适应 UI 设计与验收（2026-09）

## 设计依据

- 主任务优先：棋盘为主内容，回合、技能和操作为辅助面板。宽屏使用并列区域，窄屏改为上下排列，不把同一套固定坐标整体缩小。[Android supporting-pane 布局](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts)
- 可发现性：图标同时配技能名称；禁用技能可点击查看原因，长按查看规则。当前玩家、真人/电脑和当前阶段常驻显示；不依赖瞬时事件推断下一步。
- 触控优先：主要操作与配置按钮至少 48×48 逻辑像素，8 像素间距；棋子命中半径随棋盘缩放补偿。[Android 触控目标建议](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)
- 状态不仅靠颜色：玩家编号、阵营名、阶段文案、技能状态和选择边框提供冗余线索。小字使用深色前景与浅色底色；充能条不再使用浅底白字。[WCAG 2.2](https://www.w3.org/TR/WCAG22/)

这些原则用于改善视觉和触控体验，不代表基于画布的游戏已获得完整 WCAG 合规或屏幕阅读器支持。

## 当前布局约定

`src/ui/game_layout.rs` 统一产生逻辑坐标，相机投影、HUD 渲染和点击判定共享同一个棋盘矩形。

| 场景 | 布局与行为 |
| --- | --- |
| 宽度至少 640 且宽大于高 | 棋盘与操作面板整体居中，间隔固定 24；面板宽 280–320，棋盘按剩余空间分配，最大 960 |
| 横屏高度至少 620 | 双列技能卡，卡高 68，显示名称、次数和状态；第五张保持固定顺序，不随可用性移动 |
| 横屏高度 540–619 | 双列卡高 56，状态详情通过点按查看 |
| 横屏高度低于 540 | 三列卡高 48；回合状态与设置分占顶栏，主要操作仍在底部 |
| 竖屏 | 顶部当前回合/设置，中间棋盘，棋盘下方一排五个技能；先预留完整底部操作区，再计算棋盘大小 |
| 日志展开 | 在辅助面板内替换次级内容，棋盘与“掷骰/取消”仍保持可见；鼠标滚轮和触控拖动可滚动 |
| 技能说明 | 独立说明区，优先显示不可用原因；内容可滚动，切换技能回到顶部，右上角关闭；不覆盖技能按钮 |
| 事件提示 | 保留“触发玩家 → 事件 → 受影响玩家/飞机”；与说明、目标选择提示和日志互斥显示 |
| 配置页 | 可完整容纳时使用桌面横向分组；窄/矮窗口切换滚动配置，开始/返回固定底部，避免缩小触控目标 |
| 设置/结算 | 设置面板宽 320，高度不足时滚动；结算卡最大宽 460、随窗口收窄，两个操作按钮随卡宽重排 |

经典规则仍隐藏技能和充能，不改变玩法规则。Android 改为横竖屏全传感器方向；WASM 使用安全区和设备触控能力，渲染像素比交给引擎。

## 自动化检查

- 棋盘、技能、状态、设置、充能、主要操作的实际矩形不相交且不越界。
- 机库身份徽章按可见子元素边缘校验，不以透明父容器替代；避让棋盘、FPS 和操作区域。
- 覆盖 360×640、390×844、600×960、720×1280、640×360、1024×600、1280×720、1280×800、1920×1080、2560×1600 等逻辑尺寸，以及 539/540、619/620、739/740 断点。
- 校验棋盘世界坐标到屏幕坐标的映射、缩放后的棋子命中直径、技能/主要操作最小触控尺寸。
- 配置项实际边缘不重叠，固定页脚与滚动区分离；设置滚动后的命中映射与结算按钮渲染坐标一致。

运行 `./scripts/harness-check.sh standard`、`./scripts/harness-check.sh wasm` 和 `./scripts/harness-check.sh android`。发布用 release 构建需要另外执行，不等同于上述开发构建。

## 人工回归清单

1. 进入配置页，改变规则/玩家数，滚动至底部，检查开始/返回始终可见；滚动手势不应触发途中选项。
2. 进入对局，检查当前玩家、阶段、可用与禁用技能文案，选择目标后可取消；切换玩家时布局不跳动。
3. 点按灰色技能、长按技能、滚动说明，切换技能检查回到顶部；展开日志，确认棋盘和主要操作不被遮挡。
4. 设置弹窗阻止下层输入；短横屏可滚动访问所有设置；语言切换后不应产生按钮文字重叠。
5. 对局中旋转横竖屏、退出到菜单、进入结算页，检查窗口重排与操作命中一致。

浏览器视口模拟可能出现 CSS DPR 与底层画布物理尺寸不一致。验收必须同时记录 CSS 视口、canvas backing size 与 devicePixelRatio，不能把物理像素截图尺寸当作已验证的逻辑尺寸。真实 Android 平板的系统手势/刘海安全区与触控拖动仍需安装后实测。

## 本轮验证结果

- 2026-09-06：`./scripts/harness-check.sh all` 成功；300 个单测通过；native check、clippy、WASM check/dev 打包、Android debug APK 均完成。Clippy 仍有参数数量/类型复杂度等警告，Gradle 提示弃用 API，并非零警告构建。
- 浏览器：正常 1280×720 横屏下检查了对局、日志、自动对局完成与结算；检查了中英文设置、禁用技能说明和竖屏配置滚动。日志展开不覆盖棋盘/主操作；配置滚动时开始/返回固定。
- 响应式模拟的 CSS 360×640 对应 backing 720×1280、DPR 1，存在模拟像素比不一致；仅用于竖屏结构观察。360×640 等精确逻辑尺寸的边界依据几何单测，不将该模拟截图当作真实手机触控验收。
- 本地 `dist/` 为本次验证的 WASM **dev** 产物；Android 产物为 `platforms/android/app/build/outputs/apk/debug/app-debug.apk`。没有安装到实体平板，也没有生成本次 release 产物。
- 内嵌浏览器自动对局时出现音频 `NotSupportedError: no supported source`。已确认本地音频 HTTP 200、文件为有效 Ogg/Vorbis；原因尚未定位，未修改或重生成音频资源。对局继续运行并完成，但本轮不宣称音频播放验收通过。

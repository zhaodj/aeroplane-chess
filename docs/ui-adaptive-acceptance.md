# 自适应 UI 设计与验收（2026-09）

## 设计依据

- 主任务优先：棋盘为主内容，回合、技能和操作为辅助面板。宽屏使用并列区域，窄屏改为上下排列，不把同一套固定坐标整体缩小。[Android supporting-pane 布局](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts)
- 可发现性：图标同时配技能名称；禁用技能可点击查看原因，长按查看规则。当前玩家、真人/电脑和当前阶段常驻显示；不依赖瞬时事件推断下一步。
- 触控优先：主要操作与配置按钮至少 48×48 逻辑像素，8 像素间距；棋子命中半径随棋盘缩放补偿。[Android 触控目标建议](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)
- 状态不仅靠颜色：玩家编号、阵营名、阶段文案、技能状态和选择边框提供冗余线索。小字使用深色前景与浅色底色；充能条不再使用浅底白字。[WCAG 2.2](https://www.w3.org/TR/WCAG22/)

这些原则用于改善视觉和触控体验，不代表基于画布的游戏已获得完整 WCAG 合规或屏幕阅读器支持。

## 当前布局约定

### 换位选择与确认

- 点击换位后分步选择己方飞机、目标；只有一个候选时自动选中，仍需确认。预览显示双方高亮、双向虚线与玩家/飞机编号。
- 选择期间底部“日志”临时变为“取消”，主按钮显示当前步骤，预览后才成为“确认换位”。沿用同一组可见矩形，按钮至少 48 像素高且互不重叠；中心骰子不掷骰、不确认、不取消。
- 点击已选己方飞机或 Backspace 重选，Esc/取消退出，不扣次数。确认时重新检查状态，成功才扣充能和占用技能机会。
- 任一换位参与飞机尚未落稳时，主按钮变灰并显示“等待落稳”（英文 `Wait to land`），保留编号预览与取消入口；落稳后恢复“确认换位”，必须重新点击，不回放等待期间的确认请求。等待态复用确认按钮的实际边线和触区，横竖屏回归覆盖其文字、禁用颜色及按钮避让关系。
- 多个候选落入同一触区时，显示玩家颜色和 `P玩家 · #飞机` 编号选项；每项至少 48×48，渲染/命中共享几何，点击面板外收起，不穿透到棋盘。
- 自动回归覆盖多候选非首项选择、单候选仍确认、各阶段取消、重选、过期状态拒绝，以及横竖屏实际按钮节点的边线/命中一致性。

`src/ui/game_layout.rs` 统一产生逻辑坐标，相机投影、HUD 渲染和点击判定共享同一个棋盘矩形。

| 场景 | 布局与行为 |

| 横屏高度低于 420 | 卡高 54，32 像素图标在左、短名称在右；保留角标、至少 48 像素高的公共提示区和底部主操作 |
| 竖屏 | 顶部当前回合/设置，中间棋盘，下方一排五个技能；技能栏最大宽 512、居中，单卡最大宽 96；高度低于 740 时卡高 84/图标 40，否则卡高 92/图标 44 |

| 掷骰入口 | 中心骰子与面板“掷骰”按钮并存，共用真人待掷骰判定；中心热区随棋盘缩放，覆盖摇摆骰子与呼吸光环，至少 64×64 逻辑像素 |
| 掷骰状态 | 动画播放、双骰选择、技能目标选择、电脑回合和结算时不接受重新掷骰；中心区域继续用于双骰/飞机选择，仅面板的“取消”可取消技能目标选择 |
| 日志展开 | 在辅助面板内替换次级内容，棋盘与“掷骰/取消”仍保持可见；鼠标滚轮和触控拖动可滚动 |
| 技能说明 | 独立说明区，优先显示不可用原因；内容可滚动，切换技能回到顶部，右上角关闭；不覆盖技能按钮。区域高度不足 88 时将“技能名 · 原因”并入滚动正文首行，隐藏重复标题、缩小内边距，避免只露出标题 |
| 事件提示 | 保留“触发玩家 → 事件 → 受影响玩家/飞机”；与说明、目标选择提示和日志互斥显示 |
| 配置页 | 可完整容纳时使用桌面横向分组；窄/矮窗口切换滚动配置，开始/返回固定底部，避免缩小触控目标 |
| 全局设置入口 | 所有页面统一为右上角 48×48 圆角齿轮按钮；距可绘制窗口顶部、右侧各 16，圆角 12，图标 24；不依赖对局面板位置，与面板实际背景至少间隔 16 |
| 设置入口提示 | 悬停或触摸长按约 0.52 秒显示本地化“设置”提示；短点按打开，长按松手不打开，拖出再移回也不触发；保留悬停/按下背景反馈 |
| 设置/结算 | 设置面板宽 320，高度不足时滚动；结算卡最大宽 460、随窗口收窄，两个操作按钮随卡宽重排 |

经典规则仍隐藏技能和充能，不改变玩法规则。Android 改为横竖屏全传感器方向；WASM 使用安全区和设备触控能力，渲染像素比交给引擎。

## 自动化检查

- 棋盘、技能、状态、设置、充能、主要操作的实际矩形不相交且不越界。
- 机库身份徽章按可见子元素边缘校验，不以透明父容器替代；避让棋盘、FPS 和操作区域。
- 覆盖 360×640、390×844、600×960、720×1280、640×360、1024×600、1280×720、1280×800、1920×1080、2560×1600 等逻辑尺寸，以及 539/540、619/620、739/740 断点。
- 校验棋盘世界坐标到屏幕坐标的映射、缩放后的棋子命中直径、技能/主要操作最小触控尺寸。
- 中心热区按动画每帧的骰子四角与光环边缘校验，横竖屏始终对齐棋盘中心且不与面板按钮重叠。
- 鼠标/触摸均可从两个入口掷骰；按住不重复请求，弹窗关闭帧不穿透，动画/双骰选择期间不排队掷骰，空格与点击同时触发也不残留请求。
- 中心区域不被标记为永久 HUD 遮挡，避免拦截双骰及技能目标选择；引导文案区分待掷骰、动画播放与双骰选择。
- 配置项实际边缘不重叠，固定页脚与滚动区分离；设置滚动后的命中映射与结算按钮渲染坐标一致。
- 检查设置按钮与面板实际背景（含外扩部分）、回合摘要、棋盘和 FPS 的可见间距；跨页面检查实际按钮 Node 的位置、尺寸、圆角，齿轮所有旋转节点不越出 24×24 图标范围。
- 技能卡按实际 ImageNode、名称 Text、次数角标和状态标记的边线校验；覆盖中英文、窗口缩放/旋转及 419/420 断点，图标边缘与中心均命中对应整张卡片。
- 五个新版图标由 imagegen 生成，保留真实透明 alpha，使用 `assets/ui/skills/*-compact.png`；原插画不覆盖。完整提示词见 `docs/skill-icon-design.md`。
- 设置输入捕获明确排在平台指针更新之后；验证鼠标打开、Esc 关闭、触摸长按/短按/拖离以及松手帧不会点击穿透。

运行 `./scripts/harness-check.sh standard`、`./scripts/harness-check.sh wasm` 和 `./scripts/harness-check.sh android`。发布用 release 构建需要另外执行，不等同于上述开发构建。

## 人工回归清单

1. 进入配置页，改变规则/玩家数，滚动至底部，检查开始/返回始终可见；滚动手势不应触发途中选项。
2. 进入对局，检查当前玩家、阶段、可用与禁用技能文案，选择目标后可取消；切换玩家时布局不跳动。
3. 点按灰色技能、长按技能、滚动说明，切换技能检查回到顶部；展开日志，确认棋盘和主要操作不被遮挡。
4. 设置弹窗阻止下层输入；短横屏可滚动访问所有设置；语言切换后不应产生按钮文字重叠。
5. 对局中旋转横竖屏、退出到菜单、进入结算页，检查窗口重排与操作命中一致。
6. 分别触摸中心骰子、面板“掷骰”并检查动画；动画期间连续点击不可再次掷骰。启用双骰后点击左右骰子均可选值，不应触发新掷骰；选择技能目标时点击中心不应取消选择。
7. 主菜单、配置、对局和结算页检查齿轮位置一致；悬停/长按查看中英文提示，短点按打开。横竖屏检查按钮不贴面板，矮横屏回合摘要、技能和主操作均可见。

浏览器视口模拟可能出现 CSS DPR 与底层画布物理尺寸不一致。验收必须同时记录 CSS 视口、canvas backing size 与 devicePixelRatio，不能把物理像素截图尺寸当作已验证的逻辑尺寸。真实 Android 平板的系统手势/刘海安全区与触控拖动仍需安装后实测。

## 随机事件加盾反馈（2026-09-06）

- 不改变护盾的规则生效时机；表现顺序改为“完成移动/同色跳跃 → 落点盾牌脉冲 + 护盾 +1 浮字 → 更新护盾标记”。移动期间保留已有护盾显示，新增护盾等反馈结束后再展示。
- 按飞机实际移动动画是否结束触发，不按骰点或固定延时猜测落地；包括快速模式和额外移动等待。盾牌约 0.55 秒、浮字约 0.62 秒，新增护盾标记在落地约 0.70 秒后展示。中英文分别显示“护盾 +1”/“Shield +1”。
- 加盾目标读取结构化事件，兼容普通事件格及同色飞跃后补结算的原事件；同一事件不重复播放。飞机消失、回机库、动作被替换或退出对局时清理待播放反馈。
- 新增 7 项自动化测试，使用实际移动、特效系统与渲染实体验证：普通/同色跳跃落地时序、快慢速度、已有护盾、中英文、无位移、过期与退出清理，以及浮字行框与盾牌实际网格在缩放动画全过程中的避让。另覆盖 50–400 FPS 的计时边界，护盾延迟使用浮点秒，避免逐帧取整毫秒导致提前显示。
- `harness-check.sh standard` 和 `wasm` 通过，322 个单测通过；Clippy 仍有既存警告。本地预览更新为 WASM dev，本次未生成或安装平板 release 包。
- 浏览器 CSS 981×998、canvas 1962×1996、DPR 2：新版可进入自动对局并持续推进，检查时未见浏览器错误。精确加盾时序与几何关系以确定性自动化测试为准，不将随机自动试玩等同于实体平板专项验收。

## 换位后落点引导修复（2026-09-06）

- 根因是换位直接互换了不同玩家的相对进度，却另行交换世界坐标；掷骰引导和实际移动按相对进度计算，因此与画面位置不一致。
- 玩家和 AI 共用 `gameplay/swap_flow.rs`：根据公共棋盘位置重算双方进度，并从逻辑位置生成换位坐标，避免读到动画中途的坐标。保留玩家身份及既有护盾交换行为。
- `PieceProgress` 支持换到本方起点前两格的 `-2/-1`；移动、动画、落点引导与事件日志同步支持跨越 `0`，避免将这两格误当作冲线支路。
- 明确技能处理、掷骰结算、动画及引导更新顺序。自动化检查覆盖全部 24 种座位排列、各玩家与公共节点、真人/AI 共用入口、起点边界、非法状态，以及“换位 → 掷骰 → 可见引导/连线 → 点击命中 → 实际落点”的一致性。
- 验证：`harness-check.sh standard`、`wasm` 通过，328 个单测通过（新增 6 个）；Android Rust 编译及 debug APK 打包通过。Gradle 在沙箱内加载本机库失败，使用原脚本在沙箱外重试成功，未改依赖/构建配置；Clippy 与 Gradle 仍有既存警告。
- 浏览器自动对局可持续推进，检查时未见运行错误。本地预览为 WASM dev；未生成本次 release、未安装平板、未提交或推送代码。
